# Marketplace Release Strategy

## Objective

Distribute the Universal Matching Platform as a source-code product or application template to international buyers while avoiding claims that cannot be verified from the release package.

## Marketplace evaluation criteria

Evaluate each candidate against:

- acceptance of source-code products
- suitability for web application systems
- suitability for mobile app templates
- international buyer reach
- license compatibility
- seller verification and payout availability
- update/refund obligations
- permitted external dependencies
- asset and screenshot requirements

## Listing package baseline

Every marketplace listing should reuse the canonical package:

- MARKETPLACE_LISTING.md
- COMMERCIAL_PACKAGING.md
- SUPPORT_SCOPE.md
- FAQ.md
- LICENSE_DECISION_REQUIRED.md until a final license is approved
- verified screenshots only
- demo instructions only when an actual demo deployment exists

## Channel-specific adaptation

Do not copy a listing blindly between marketplaces. Adapt title, category, screenshots, supported platforms, installation prerequisites and license wording to the marketplace's current rules.

## Pre-publication rule

Marketplace selection is not complete until the owner verifies the marketplace's current seller, product-category, payout and licensing requirements.
